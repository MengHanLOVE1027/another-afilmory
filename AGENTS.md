# AGENTS.md

## Project

This repository is **Another-Afilmory**, a local-first personal photography site forked from [Afilmory](https://github.com/Afilmory/afilmory). The active product is `apps/web`; the official Hono/Postgres/Redis backend and its dashboard have been removed from this fork.

### Stack

- React 19, Vite 8, TypeScript, Tailwind CSS 4, Motion
- Jotai, React Router, TanStack Query/Virtual
- `node:sqlite` for accounts, sessions, content and bookings
- Local photo storage plus Sharp thumbnails/previews
- Vite middleware for `/api/*`, RSS and sitemap

## Commands

Run from the repository root:

```bash
pnpm dev:lan                 # http://0.0.0.0:5199
pnpm build:manifest          # rebuild photos-manifest.json
pnpm reset:password <email> <new-password>
```

Useful checks:

```bash
.\node_modules\.bin\tsc.cmd -p apps/web/tsconfig.json --noEmit
pnpm --filter @afilmory/web build
```

The admin API only exists while the Vite dev server is running. A plain static `apps/web/dist` deployment has no `/api/*`.

## Layout

```text
apps/web/                 main site and /console admin
  src/pages/              home, gallery, albums, categories, booking, about, console
  src/modules/            gallery, discover, viewer, map, metadata
  src/lib/admin/          admin types, permissions, auth, bookings
  plugins/vite/           admin-data, admin-db, admin-files, admin-jobs, admin-log, feed-sitemap, OG
  public/                 photos, thumbnails, previews, icons
packages/                 Afilmory builder/data/ui/typing packages
content/                  SQLite database, backups, seed JSON
photos/                   original photos
docs/                     admin notes and screenshots
```

Do not recreate `be/`, Docker Compose files or a separate backend for this project.

## Architecture

1. `content/afilmory.db` stores `users`, `sessions`, `settings`, `app_meta`, `trash` and `bookings`.
2. Site content lives in the SQLite `settings` row `admin-data`; `content/admin-data.json` is only a first-run seed.
3. `apps/web/plugins/vite/admin-db.ts` owns users, sessions and passwords.
4. `admin-data.ts` exposes `/api/admin/*` and `/api/auth/*`; it validates permissions server-side.
5. `admin-files.ts` handles uploads/deletes, incremental public-photo sync and manifest rebuilds.
6. `admin-jobs.ts` runs the asynchronous reindex job; `admin-log.ts` keeps the in-memory admin log ring.
7. Photos are served from `public/photos`; admin previews use `/previews/<id>.jpg`.
8. `PageHeader` is shared by all public pages. The site is dark-only: `index.html` sets `data-theme="dark"`.
9. Permissions are role-based. Contributors may only see/edit/delete their own photos.

## Configuration

- `config.json` is the base site config (name, title, description, URL, author, social links, feed, map).
- `site.config.ts` merges `config.json` with `builder.config.ts`.
- Admin-edited site/home/about values live in SQLite and override the defaults.
- When changing default branding, update all of: `config.json`, `site.config.ts`, `apps/web/src/lib/admin/types.ts`, `content/admin-data.json`, README/docs, and the live SQLite row if present.

## Conventions

- Pages generated by `vite-plugin-route-builder` must export `const Component`, not a default export.
- After adding/removing a page, restart Vite so `generated-routes.ts` is regenerated.
- Use `PageHeader` for public pages and keep the dark palette via `--site-*` / `--header-*` variables.
- Prefer `/previews/*` for grid/hero images; do not decode multi-megabyte originals for thumbnails.
- Preserve the existing files in `content/` and `photos/` unless the task explicitly asks to delete data.
- Do not rename workspace package identifiers (`@afilmory/web`, `@afilmory/builder`, etc.); pnpm filters and imports depend on them.

## Windows caveat

PowerShell `Get-Content` / `Set-Content` can corrupt Chinese source files through the active code page. Use the editor/write tools or Node.js UTF-8 I/O; never bulk-rewrite `.ts`/`.tsx` with PowerShell text cmdlets.

## Validation

For UI/admin changes:

1. Run the TypeScript check above.
2. Start `pnpm dev:lan` and smoke-test `/`, `/gallery`, `/booking`, `/about` and `/console`.
3. Confirm the admin login and one save operation still work.
4. For production output, run `pnpm --filter @afilmory/web build`.
